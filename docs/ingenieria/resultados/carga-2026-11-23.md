## Repetición del escenario de 10 usuarios

La medición inicial preparaba cada cliente HTTP dentro de la tarea concurrente. En este equipo,
crear diez clientes tomó 4,46 s y bloqueó el bucle del generador mientras ya se cronometraban
las primeras solicitudes. La nueva medición prepara las diez sesiones antes de cronometrar
cada oleada.

Se ejecutaron tres oleadas contra Docker Desktop con PostgreSQL 16, una API y un worker, con el
modelo de demostración. Cada ejecución completó los 30 flujos.

| Configuración del backend con el generador corregido | p50 de login (ms) | p95 de login (ms) | p99 de login (ms) |
| --- | ---: | ---: | ---: |
| Antes de liberar la conexión durante bcrypt | 701,29 | 897,19 | 911,78 |
| Después de liberar la conexión durante bcrypt | 627,72 | 772,13 | 802,16 |

El login ya se ejecutaba en los hilos de FastAPI. En el contenedor, diez verificaciones bcrypt de
costo 12 terminaron juntas en 0,44–0,47 s. La API ahora devuelve la conexión al pool antes de
verificar la contraseña y comprueba de nuevo las credenciales antes de responder con el token.

En un microbenchmark de solo login contra Uvicorn local, con SQLite temporal y diez cuentas
distintas, el p95 de 30 solicitudes pasó de 748,81 ms a 630,99 ms.
